What the course asks for in Phase 2 [E 4-10]: use PyDI; try blockers, several similarity
measures, matching rules AND learned matchers; evaluate with P / R / F1 and reduction ratio;
three labelled sets (train / validation / test), each >= 300 pairs; ~20% random matches,
~50% corner cases, ~30% random non-matches, manually checked [E 8, L 34]; pair completeness
> 0.97 [L 37]; do not report pair quality [T]; report a table
"# | Matcher | Blocker | P | R | F1 | # Corr | Time" and the group size distribution [E 10];
match at least two dataset pairs, through a "connector" dataset, often the largest [T].

WHAT WENT WRONG
  Precision is 1.000 and the best threshold is the lowest one we allow (0.30). That looks great
  but is meaningless: the random non-matches are so different that nothing can score as a false
  positive, so the threshold falls to the floor and every candidate becomes a correspondence -
  133,694 correspondences for 22,697 Wikidata records. The group size distribution showed it at
  once: groups of up to 11,422 records. Exactly the warning of the notebook: "your evaluation is
  only as good as your evaluation set" and look at the cluster sizes [T]. Recall is only the
  blocking loss. -> Round 2: real labels with corner cases, and a better blocker.

WHAT WE LEARNED
  1. A name alone is not enough once the labels contain look-alikes: precision drops to ~0.66
     whatever measure we use ("Seisen University" Tokyo vs Nagano, "Pacific University" US vs IN).
     Which measure hardly matters; Jaro-Winkler keeps the most recall.
  2. The web domain is what makes rules precise (.66 -> .96-.98). Unlike our earlier run, adding
     city / year / position to the rule helped a little (W-R .880 -> .929) - with harder labels
     every extra hint counts.
  3. Learned matchers win (W-R .964, D-R .953), mainly through recall: they learn that a missing
     year or website is not evidence against a match (the "has_..." features) [L 13, L 75].
  4. One-to-one (greedy) is the best global matching; maximum bipartite loses a lot of recall
     because maximising the SUM of scores swaps strong pairs for several weak ones [L 19].
  5. FAILURE: for D-R our script picked "no one-to-one" because its validation F1 was 0.013
     higher. On the test labels that choice dropped precision to 0.885, and the group size
     distribution showed groups of up to 4,509 records. A metric on 300 labelled pairs cannot see
     that one record is matched to 20 others - the cluster sizes can [T].

  Error analysis (validation, 05_final/results/errors_*_r2.csv):
     - names in another language: "Ibero-American University of Torreon" vs
       "Universidad Iberoamericana Torreon"
     - part against the whole: "Pacific University Health Professions Campus" vs "Pacific
       University Oregon", "South University-West Palm Beach" vs "South University", a research
       unit of Avignon University vs the university
     - renamed institutions (cannot be fixed with these data)
     - look-alikes: "NHL" vs "HZ University of Applied Sciences", "IPAG" vs "ISG"


5. ROUND 3 - FIXES FROM THE ERROR ANALYSIS                  (labels round 2)
------------------------------------------
  a) translate common words in names before comparing (universidad/universita/... -> university,
     accademia -> academy, belle arti -> fine arts ...; a word list, no external service) [L 16-17]
  b) a new feature "part_word": 1 if both or neither name contains campus / branch / centre /
     faculty / laboratory ..., 0 if only one does
  c) always enforce one-to-one (greedy), because the sources are duplicate-free [T]

  Blocking with translated names: unchanged (W-R PC 0.993, D-R 0.972 with the embedding pass).
  Matching (validation):

  How it went:
     a) translation: no real effect (-0.007 to +0.001 F1 per matcher, before one-to-one). Most of these
        pairs were already caught through the alternative names, which often contain the English
        or the local form. Kept, because it costs nothing.
     b) part_word: did NOT help (-0.004 to +0.004 F1, no consistent direction). Too few labelled campus pairs for the
        learner to use it, and many parts do not carry such a word in their name.
     c) one-to-one always: the clear win. Group sizes are now only 2 and 3 (see Section 7).

     W-R  logistic regression + greedy one-to-one   P 0.982  R 0.894  F1 0.936   14,824 corr.  237 s

8. COMPARING AND COMBINING APPROACHES
-------------------------------------
  Compared:   one name measure  <  name + country rule  <  rule with domain  <  rule with all
              attributes  <  learned matchers;  greedy = stable > bipartite.
  Combined (used in the final pipeline):
    - multi-pass blocking: country-scoped name tokens UNION shared domain UNION embedding
      neighbours [L 31] - each pass finds matches the others miss (domain: renamed universities;
      embedding: other spellings)
    - several measures of the same attribute as features, the learner picks [L 71]
    - learned matcher -> threshold on validation -> greedy one-to-one -> clusters
  Tried and rejected:  the "part_word" feature, picking "no one-to-one" by F1, maximum bipartite.
  Not tried, and why:
    - LLM matcher [T, L 88]: needs a paid API key. Would fit the uncertain band only
      (scores 0.4-0.7), a few hundred pairs; we leave the decision and the key to the team.
    - character 3-gram blocking: 2.1 billion candidate pairs, not runnable.


9. EARLIER ATTEMPT (branch "legacy") AND WHY THE NUMBERS DIFFER
---------------------------------------------------------------
  The first version took ~50,000 labelled pairs straight from the ID links, unchecked, with
  dev/test only. It reported F1 96-99%. With checked labels that include corner cases the same
  kind of pipeline reaches 93-94% on test. The data did not get harder - the evaluation set got
  honest. Same lesson as round 1, at a smaller scale [L 36].
